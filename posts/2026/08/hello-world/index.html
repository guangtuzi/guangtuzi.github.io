从这里开始：一份技术博客的自我说明

为什么要写这个博客，以及我希望用怎样的方式记录技术判断、工程取舍和长期经验。

发布于2026年8月28日
阅读2 分钟 · 530 字

技术工作里最容易丢失的，往往不是代码，而是当时为什么这样做。

一次排障结束后，我们记得改了哪一行，却忘了哪个信号真正帮助我们缩小范围；一个架构上线后，我们记得最终结构，却忘了它是在怎样的业务约束和团队能力下成立。时间一久，结论还在，语境消失了。

这个博客想保留的正是那部分语境。

我会记录什么

这里不会追逐每一个新名词。我更希望围绕三类内容持续写作：

  1. 问题如何被定义。 一个准确的问题，通常比十个仓促的答案更有价值。
  2. 方案如何被取舍。 性能、复杂度、交付速度和可维护性很少能同时最大化。
  3. 结果如何被验证。 可以观测、可以复现、可以被推翻的结论，才有继续讨论的意义。

用长期视角维护内容

技术文章不是发布即完成。依赖会升级，平台会变化，曾经正确的最佳实践也会过期。因此每篇文章都会显示更新时间；如果结论发生变化，我会直接修订原文，并说明变化的原因。

博客本身也保持公开：它由 Hexo 生成，通过 GitHub Actions 构建并部署到 GitHub Pages。写作、代码和发布在同一套版本历史中，任何变化都有迹可循。

这是第一篇，也是一个简单的约定：把复杂问题讲清楚，把关键判断留下来。
